# AI Context

## 目的

- MemoPolish は、PC とスマホの間で短いフレーズを素早く共有する `PhraseBridge` 系アプリ。
- 主価値は「認証なしでも軽く共有できること」と「保存・削除に最低限の保護があること」。
- AI 加工は補助機能であり、通常の保存・共有フローを置き換えない。

## 対象ユーザー

- 自分の複数端末間で短文を受け渡したい個人ユーザー
- Gmail 下書きやチャットへの一時貼り付けより軽い導線を求めるユーザー
- 要確認: チーム共有を主対象にするか、個人利用を主対象にするかの優先度

## 主要価値

- 認証なしで即使える
- `bucket_id` 共有で複数端末から同じ一覧を見られる
- `write_key` により保存・削除を最低限保護する
- AI が失敗しても保存・共有は継続できる
- 1 画面で主要操作が完結する

## Core Workflow

1. ユーザーがフレーズを入力する
2. `bucket_id` に紐づく一覧を取得して現在の共有内容を確認する
3. フレーズを保存する
4. 必要に応じて AI 加工を実行する
5. 加工結果または保存済みフレーズをコピーする、または削除する

AI 加工は保存フローの補助機能であり、必須ではない。通常の保存・共有は AI なしで完結する。

## 主要機能

- フレーズ保存
- `bucket_id` 単位の一覧取得
- コピー
- 削除
- cleanup による期限切れ削除と件数上限維持
- AI 加工
  - `polish`
  - `keigo`
  - `keypoints`
- PWA としてのホーム画面追加

## 設計方針

- 1 画面完結を優先する
- UI にサーバ責務や秘密情報を寄せすぎない
- 外部接続は既存の API / lib 分離を守る
- `bucket_id` と `write_key` と `write_key_hash` の役割を混ぜない
- AI 加工は API 境界で入力制約と出力ポリシーを守る
- `PolishForm.tsx` は中核だが、大規模再構成は通常タスクと分ける

## UX 方針

- 操作の軽さを優先する
- 反応のないフォームに見せない
- 保存、取得、削除、AI 加工の主要導線を 1 画面に集約する
- スピナー、トースト、未保存表示、削除時フィードバックを維持する
- モバイル利用を前提に崩さない

## 非目標

- 認証機能の追加
- 複雑な状態管理の導入
- AI を前提にした保存フローへの変更
- UI からの service role key 相当処理
- API レスポンスの PWA キャッシュ
- 要確認: 共有リンク、招待、履歴検索などの高度共有機能

## 制約

- `bucket_id` は 22 文字以上
- `write_key` 平文は DB に保存しない
- `write_key_hash` はサーバ送信用
- フレーズは 2000 文字以内
- `extraInstruction` は 500 文字以内
- 期限切れは 7 日
- 1 bucket あたり最大 200 件
